---
title: 今日の一問 · 3619. 価値の合計が K で割り切れる島の数
summary: 未訪問の陸地から四方向 DFS で島全体を巡り、値の合計を k で割った余りから数えるか判断する。
---

島の個数に加え、島全体の価値が k で割り切れるという条件がある。私は DFS で四方向につながる陸地区域を見つけ、探索中に値を足し、最後に判定する方法を使った。

## 島全体を見つけてから価値を判定する

0 は水、正の整数は陸地を表す。上下左右の隣接だけが接続であり、斜めの接触は含まない。

各マスを個別に剰余判定したり、陸地のマス数だけを数えたりしてはいけない。同じ島の全数値を足す必要がある。

```text
島の総価値 = 同じ連結領域の陸地の値の総和

総価値 % k == 0
    → この島を答えに加える
```

例えば隣り合う値が 2、3 で k = 5 なら、個別には割り切れなくても、島の合計は 5 なので数える。

## map で訪問状態を記録する

grid と同じ大きさの真偽値行列 map を作る。map は変数名で、実際の型は vector<vector<bool>>。各マスを訪問済みか記録する。

外側の二重ループで各位置を調べ、次の二条件を満たすときだけ新しい DFS を始める。

- 値が 0 でなく、陸地である。
- まだ訪問していない。

DFS が同じ島の陸地をすべてマークするので、外側のループで再び同じ島を見てもスキップし、二重に数えない。

値が非負という条件から、この問題では「0 でない」と「正の整数の陸地」が等価である。

## loop による四方向の探索

loop に入るたび、まず次を行う。

```cpp
map[i_n][j_n] = true;
sum += grid[i_n][j_n];
```

次に上、下、左、右の順で隣を確認し、範囲内・陸地・未訪問の場合だけ再帰する。

訪問マークは隣を探索する前に付ける。そうしないと隣同士で再帰し合ったり、同じ値を複数回加算したりする可能性がある。

判定順にも意味がある。座標の合法性を先に確認し、論理積の短絡評価で grid や map の範囲外参照を防ぐ。

## sum を参照渡しする理由

最後の引数 long int& sum により、全再帰呼び出しが同じ累算器を扱い、新しい陸地に入るたびに価値を足す。

外側で新しい島を見つけるごとに sum = 0 を作って DFS を呼ぶので、島同士の合計は混ざらない。

DFS から戻れば島全体の探索が終わっている。その時に sum % k を一度だけ判定し、探索途中の合計が割り切れたという理由では答えを増やさない。

## グリッドの例

k = 5 とする。

```text
2  3  0
0  0  4
6  0  1
```

| 島 | 含まれる値 | 総価値 | 数えるか |
| --- | --- | ---: | --- |
| 一つ目 | 2、3 | 5 | はい |
| 二つ目 | 4、1 | 5 | はい |
| 三つ目 | 6 | 6 | いいえ |

3 と 4 は斜めに近いだけなので別の島であり、答えは 2 となる。

一つ目の DFS 後は 2、3 のマークが true となり、外側が 3 に来てもスキップする。4、1 と 6 はそれぞれ別の DFS を始める。

## C++ 実装

以下は元のコード。

```cpp
class Solution {
public:
    int loop(vector<vector<int>>& grid, vector<vector<bool>>& map, int i_n, int j_n, int m, int n, long int& sum) {
        map[i_n][j_n] = true;
        sum += grid[i_n][j_n];
        if (i_n - 1 >= 0 && grid[i_n - 1][j_n] != 0 && !map[i_n - 1][j_n]) {
            loop(grid, map, i_n - 1, j_n, m, n, sum);
        }
        if (i_n + 1 < m && grid[i_n + 1][j_n] != 0 && !map[i_n + 1][j_n]) {
            loop(grid, map, i_n + 1, j_n, m, n, sum);
        }
        if (j_n - 1 >= 0 && grid[i_n][j_n - 1] != 0 && !map[i_n][j_n - 1]) {
            loop(grid, map, i_n, j_n - 1, m, n, sum);
        }
        if (j_n + 1 < n && grid[i_n][j_n + 1] != 0 && !map[i_n][j_n + 1]) {
            loop(grid, map, i_n, j_n + 1, m, n, sum);
        }
        return sum;
    }

    int countIslands(vector<vector<int>>& grid, int k) {
        int m = grid.size();
        int n = grid[0].size();
        int answer = 0;
        vector<vector<bool>> map(m, vector<bool>(n, false));
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] != 0 && !map[i][j]) {
                    long int sum = 0;
                    loop(grid, map, i, j, m, n, sum);
                    cout << sum << endl;
                    if (sum % k == 0) {
                        answer++;
                    }
                }
            }
        }
        return answer;
    }
};
```

## 実装で気を付ける点

sum は参照で更新され、主関数は loop の戻り値を使わない。補助関数を void にすると分かりやすいが、ここでは元の int 戻り値を残している。

合計は大きくなりうるため、十分に広い型が必要だ。long int の幅は環境依存で、名前だけで 64 ビットとは言えない。汎用版では累算器を long long に統一し、補助関数を void にして、返却時に int へ変換しない形がよい。現在の戻り値は集計に使わないが、累算器と型が不一致である。

cout は各島の総価値を観察するデバッグ出力で、答えには関係しない。正式利用では削除し、余分な出力や頻繁なフラッシュのコストを避けられる。

再帰深度は島の形に依存する。細長い陸地では深くなるため、スタックが足りなければ明示スタックの DFS やキューの BFS に置き換える。探索と加算の考え方は変わらない。

## 正しさの説明

未訪問の陸地から、DFS は四方向の未訪問陸地だけへ進むので、水を越えたり別の領域に移ったりしない。始点につながる陸地は何らかの陸地経路で発見できるため、一回の DFS は一つの島をちょうど覆う。

各マスは入った直後にマークされ、再加算されない。探索終了時の sum は島全体の価値に等しい。

外側のループは全島を発見し、各島で一度だけ DFS を起動する。完全な合計が k で割り切れるかを判定することで、要求される島の数が得られる。

## 計算量

- 時間は O(m × n)。全マスを走査し、各陸地の訪問は最大一回、確認方向は四つだけ。
- 補助空間は O(m × n)。訪問行列に加え、最悪の再帰スタックも O(m × n) となる。

「連結領域を見つける」と「領域が条件を満たすか」を分けるとよい。DFS で一領域を列挙し、累算器で情報を集め、探索後に最終判定する。
