グリッドの左上から右下へ、右または下だけに移動する問題。経路のコストは通った全マスの値のビット XOR で、始点と終点も含む。すべての合法経路のうち最小のコストを返す。

私のコードは動的計画法を使うが、各マスに最小値を一つ保存するのではなく、到達時に可能なすべての XOR 結果を集合に残す。最後に終点の集合から最小値を探す。

## 考え方：全経路ではなく、可能な全結果を記録する

経路を一本ずつ列挙すると、異なる経路で同じ XOR 値が何度も現れる。同じマスに同じ XOR 値で着けば、その後に同じ道を進んだ結果も同じになるため、それまでの具体的な経路を区別する必要はない。

`unordered_set` で、この重複状態をまとめる。保存するのは「この位置へどの XOR 値で到達できるか」であり、経路そのものや出現回数ではない。

## 現時点の最小値だけでは足りない理由

通常の最小経路和は加算の大小関係を使えるが、XOR は大小順を保たない。例えば二つの前半の結果が 1 と 3 で、次の値が 2 なら、

```text
1 ^ 2 = 3
3 ^ 2 = 1
```

今は大きい 3 が、その先では小さい 1 になる。途中で最小の 1 だけを残すと、後で有利になる状態を捨ててしまう。

したがって「各マスに到達する最小 XOR 値」だけを状態として次へ渡すことはできない。異なる到達可能な XOR 結果をすべて保つ必要がある。

## 状態の定義と初期化

`dp[i][j]` を、`(0, 0)` から `(i, j)` までの全合法経路で得られる XOR 値の集合とする。

最初はすべて空集合にする。始点ではまだ移動していない経路が一つあり、始点の値も含めるので、初期状態は次のとおり。

```text
dp[0][0] = { grid[0][0] }
```

0 を入れてから始点を別に XOR する形ではない。このコードでは初期化で始点を計上し、その後の遷移では新しく着いたマスだけを加える。

## 上と左から遷移する

右と下にしか進めないので、`(i, j)` への最後の一歩は二つの位置のどちらかから来る。

- 上 `(i - 1, j)`：集合の各 `x` について `x ^ grid[i][j]` を現在の集合へ挿入する。
- 左 `(i, j - 1)`：同様に各 `x` から `x ^ grid[i][j]` を挿入する。

概念的には二つの集合の和集合を取る。

```text
dp[i][j] = { x ^ grid[i][j] | x ∈ dp[i - 1][j] }
         ∪ { x ^ grid[i][j] | x ∈ dp[i][j - 1] }
```

上や左が存在しない場合は飛ばす。最上行は左から、最左列は上からしか来られない。始点にはどちらもないので、初期状態がそのまま残る。

上から下、左から右の順に処理するため、現在のマスを計算するときには上と左が確定しており、未完成の状態を読まない。

## 例で確認する

次のグリッドを考える。

```text
1  1  1
3  1  2
```

各位置の状態は以下のとおり。集合内部の順序には意味がない。

| 位置 | 到達可能な XOR 値の集合 |
| --- | --- |
| (0, 0) | {1} |
| (0, 1) | {0} |
| (0, 2) | {1} |
| (1, 0) | {2} |
| (1, 1) | {1, 3} |
| (1, 2) | {1, 3} |

`(1, 1)` では上から `0 ^ 1 = 1`、左から `2 ^ 1 = 3` を得るため、両方を残す。

終点では上から `1 ^ 2 = 3`、左の二状態からそれぞれ 3 と 1 を得る。挿入時に重複を除き、最終集合は `{1, 3}`、答えは 1 となる。

最小の前半だけでは誤ることも分かる。`(1, 1)` で 3 を捨てると、終点では 3 しか得られず、本当の最適値を逃す。

## C++ 実装

以下は元のコードをそのまま掲載する。

```cpp
class Solution {
public:
    int minCost(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        vector<vector<unordered_set<int>>> dp(
            m, vector<unordered_set<int>>(n)
        );

        dp[0][0].insert(grid[0][0]);

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (i > 0) {
                    for (int x : dp[i - 1][j]) {
                        dp[i][j].insert(x ^ grid[i][j]);
                    }
                }

                if (j > 0) {
                    for (int x : dp[i][j - 1]) {
                        dp[i][j].insert(x ^ grid[i][j]);
                    }
                }
            }
        }

        return *min_element(
            dp[m - 1][n - 1].begin(),
            dp[m - 1][n - 1].end()
        );
    }
};
```

`unordered_set` は要素順を保証しないので、`begin()` の要素をそのまま答えにしてはいけない。コードでは `min_element` で終点集合を走査し、最小値を探す。

空でない長方形グリッドで障害物がなく、右・下に進めるなら必ず終点へ到達できるため、終点集合は空にならない。一マスだけなら遷移は行われず、そのマスの値を返す。

## 正しさの説明

始点集合は唯一の合法経路の XOR 値をちょうど含むので、初期化は正しい。

上と左の集合が完全かつ正しいと仮定する。現在のマスへ来る経路の最後の一歩は必ずそのどちらかからであり、前半の XOR に現在値を XOR すれば全経路のコストになる。よって合法経路の結果を漏らさず挿入できる。

逆に、各挿入値は合法な前半経路に現在のマスを加えて作られ、存在しない経路の値は生まれない。重複除去は同じ結果をまとめるだけで、後に得られる値を変えない。

処理順にこの性質を始点から終点へ広げられる。終点集合は全合法経路のコストをちょうど含むため、その最小値が求める答えである。

## 計算量

各マスの到達可能 XOR 値の集合サイズが最大 K とする。

- 期待時間計算量は O(m × n × K)。各マスで上・左それぞれ最大 K 状態を列挙し、ハッシュ集合への挿入は平均 O(1)。最後の最小値探索には O(K) が必要。
- 補助空間は O(m × n × K)。この実装は各マスに状態集合を保存する。

K は入力の値域と実際の到達結果に依存する。二次元 dp というだけで O(m × n) としてはいけない。集合は重複経路の記録を減らすが、異なる XOR 状態には時間と空間が必要となる。

鍵は、XOR では「今小さければ、その先でも有利」とは限らないこと。異なる到達値をすべて残し、終点で初めて大小を比べることで、答えを早く捨てるのを防げる。
