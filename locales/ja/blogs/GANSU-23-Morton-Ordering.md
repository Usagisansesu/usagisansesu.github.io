6 月 26 日から Morton 順序へ進んだ。幾何的に近い格子点を近いアクセス位置にまとめ、後の分割、AO スクリーニング、バッチ処理に別の配置を与えることが目的だった。

## 三次元座標から一次元整数へ

典型的には x、y、z を有限ビットの整数に量子化し、各方向のビットを交互に並べて Morton code を作る。その整数キーでソートすると、空間近傍性を近似的に保つアクセス順が得られる。

距離を厳密にソートするわけではない。隣り合う点でも符号の不連続境界をまたぐ場合がある。効果はソート速度だけでなく、最終 bin の範囲、active AO、実際の処理量で評価する。

## seed と符号は異なる層

当時は原子や近い原子対から seed を作り、点を最も近い seed へ割り当てる処理も含まれていた。seed はグループを作り、Morton code はグループ内やより広い範囲の空間順序を決める。

両者のパラメータを混同してはいけない。seed 集合の変更も bin 容量の変更も、後の AO リストと処理量を変えうる。

## 量子化の範囲もアルゴリズムの定義

6 月の資料はグループの包囲箱による正規化を説明していた。後の BGM 対応では大域的な 16 ビット座標量子化を使い、seed ID を複合キーに含めた。異なる段階の規約であり、後の実装詳細を初期版に書き戻してはいけない。

一方向の範囲がゼロの場合や、点が境界上にある場合の量子化、切り詰め、同じキーの処理を明確にする。並べ替えた point ID は重みと AO データにも反映し、座標だけを動かしてはいけない。

## Octree と公平に比較する

格子、AO しきい値、XC バックエンドを固定し、分割構築コスト、bin 形状、AO 対の処理量、全 XC 時間を記録する。scalar kernel から cuBLAS への変更を同時に行うと、効果全体を空間順序へ帰属できない。

Morton の価値は、ほかの処理と組み合わせられるデータ整理方法にある。Octree を上回るかは分子、基底関数系、後続計算に依存し、一回の好結果をすべての場面の優位性に一般化する必要はない。

この段階から最適化の問いは、「GPU で式をどう計算するか」から「同じ式に、ハードウェアに適したデータをどう読ませるか」へ移っていった。
