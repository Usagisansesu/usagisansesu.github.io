2025 年 11 月のミーティング資料には、実行可能な Python の HF 学習コードが含まれていた。この試作の価値は速度ではなく、抽象的な自己無撞着過程を、途中で確認できる行列演算に分解したことにある。

## 最初に入力の規約を固定する

H₂ は入門に適した系だが、小分子だからといって座標単位、基底関数系、占有数を省略してよいわけではない。元の資料には bohr 単位の座標がある。追記する例でも単位を明示し、同じ数値を Å とみなしてエネルギーを比較しないようにする。

学習用の試作では PySCF で分子を定義して積分を取得した。これにより HF ループに集中しながら、信頼できる積分を参照できる。行列演算と反復過程を自作したことは、基底関数の解析や分子積分エンジンを一から実装したこととは異なる。

## 最小限の試作に必要な量

入力を固定したら、S、運動エネルギーと核引力からなる H、および二電子積分が必要になる。直交化行列を構築し、初期密度を与える。閉殻・スピン和を取った密度の規約では、次のようになる。

```text
P = 2 Cocc Coccᵀ
F = H + J[P] - 1/2 K[P]
Eelec = 1/2 Tr[P(H + F)]
Etot = Eelec + Enuc
```

係数は密度の規約に依存する。P が二重占有の因子を含まないなら、Fock 行列やエネルギー式の係数も変わる。異なるプログラムから半分ずつ式を持ってきてはいけない。

## 各更新を観察できる手順にする

反復ごとに電子エネルギー、全エネルギー、密度変化のノルム、軌道の直交誤差を出力できる。AO 空間が小さければ J、K、F の一部も表示し、自作の縮約が直接ループと一致するか調べられる。

擬似コードの流れは次のとおり。

```text
積分を読み込み、直交化変換を構築
while 未収束:
    P から J、K、F を構築
    直交基底で固有値問題を解く
    占有軌道から P_new を生成
    エネルギーと密度の変化を比較
    P を更新
```

実装では、エネルギーが新旧どちらの密度に対応するか、収束判定後に最終再計算を行うかも明確にする。異なる反復状態を混ぜると、気づきにくい「最後の一回の誤差」が生じる。

## PySCF とどう比較するか

同じ幾何構造、単位、基底関数系、電荷、スピン、手法で比較する。初期推定と収束しきい値も記録する。全エネルギーが違う場合は、まず核間反発の加算と電子数を確認し、次に積分インデックスや交換項を調べる。

これは GANSU の本番実装ではなく、今回の追記時に再実行したものでもない。学習段階で HF 方程式を検証可能な計算の流れへ変換した記録であり、その分解の考え方は後の CUDA・DFT 開発にも引き継がれた。
