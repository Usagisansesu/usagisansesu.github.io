题目要求从网格左上角走到右下角，每步只能向右或向下。路径代价是沿途所有格子数值的按位异或，起点和终点都要计算，最终返回所有合法路径中的最小代价。

我的代码使用动态规划，不过每个格子保存的不是一个最小值，而是一个集合：把到达这里的所有可能异或结果都记录下来。最后再从终点的集合中找出最小值。

## 核心思路：记录所有可能结果，而不是所有路径

如果逐条枚举路径，不同路径可能反复得到相同的异或值。到达同一个格子后，只要当前异或值相同，后续走同一段路就会得到相同的结果，因此不必区分这两条路径的具体走法。

代码用 `unordered_set<int>` 合并这样的重复状态。它保存的是“到达这个位置可能有哪些异或值”，而不是路径本身，也不是出现次数。

## 为什么不能只保存当前最小值

普通的最小路径和可以利用累加的大小关系，但异或不保持大小顺序。例如两个前缀结果分别为 1 和 3，下一格的值为 2：

```text
1 ^ 2 = 3
3 ^ 2 = 1
```

当前较大的 3，继续走后反而得到较小的 1。如果在中途只保留最小值 1，就会丢掉后面可能更优的状态。

因此，不能把状态写成“到达每个格子的最小异或值”，再直接用这个最小值继续转移。这里需要保留全部不同的可达异或结果。

## 状态定义与初始化

令 `dp[i][j]` 表示：从 `(0, 0)` 到达 `(i, j)` 的所有合法路径，可能得到的异或值集合。

开始时，所有集合都为空。起点只有一条尚未移动的路径，而且起点本身也属于路径，所以初始化为：

```text
dp[0][0] = { grid[0][0] }
```

这里不是先放入 0 再额外异或起点。当前代码在初始化时就计入了起点，后面每次转移只计入新到达的格子。

## 从上方和左方转移

由于只能向右或向下，到达 `(i, j)` 的最后一步只可能来自两个位置：

- 上方 `(i - 1, j)`：枚举该集合中的每个 `x`，把 `x ^ grid[i][j]` 插入当前集合。
- 左方 `(i, j - 1)`：同样枚举每个 `x`，插入 `x ^ grid[i][j]`。

概念上就是把两部分取并集：

```text
dp[i][j] = { x ^ grid[i][j] | x ∈ dp[i - 1][j] }
         ∪ { x ^ grid[i][j] | x ∈ dp[i][j - 1] }
```

不存在的上方或左方直接跳过。第一行只能从左边来，第一列只能从上边来；起点两边都不存在，因此会保留初始化的状态。

代码按从上到下、从左到右的顺序遍历。处理一个格子时，上方与左方已经计算完毕，转移不会读取尚未完成的状态。

## 用一个例子走一遍

考虑下面的网格：

```text
1  1  1
3  1  2
```

各位置对应的状态如下，集合内的顺序没有意义：

| 位置 | 可达异或值集合 |
| --- | --- |
| (0, 0) | {1} |
| (0, 1) | {0} |
| (0, 2) | {1} |
| (1, 0) | {2} |
| (1, 1) | {1, 3} |
| (1, 2) | {1, 3} |

在 `(1, 1)`，从上方得到 `0 ^ 1 = 1`，从左方得到 `2 ^ 1 = 3`，所以两种状态都要保留。

到终点时，从上方得到 `1 ^ 2 = 3`；从左方的两种状态分别得到 3 和 1。插入集合后去重，最终得到 `{1, 3}`，答案为 1。

这也说明只留最小前缀会出错：若在 `(1, 1)` 丢弃 3，终点就只能得到 3，错过真正的最优结果。

## C++ 实现

下面保留我的原代码：

```cpp
class Solution {
public:
    int minCost(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        vector<vector<unordered_set<int>>> dp(
            m, vector<unordered_set<int>>(n)
        );

        dp[0][0].insert(grid[0][0]);

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (i > 0) {
                    for (int x : dp[i - 1][j]) {
                        dp[i][j].insert(x ^ grid[i][j]);
                    }
                }

                if (j > 0) {
                    for (int x : dp[i][j - 1]) {
                        dp[i][j].insert(x ^ grid[i][j]);
                    }
                }
            }
        }

        return *min_element(
            dp[m - 1][n - 1].begin(),
            dp[m - 1][n - 1].end()
        );
    }
};
```

`unordered_set` 不保证元素有序，所以不能直接把 `begin()` 指向的元素当作答案。代码使用 `min_element` 遍历终点集合，找到其中的最小值。

对于非空矩形网格，在没有障碍、只能向右或向下的条件下，总有路径到达终点，因此终点集合不会为空。若网格只有一个格子，两个转移分支都不执行，返回的就是该格子的值。

## 正确性说明

起点集合恰好包含唯一合法路径的异或值，因此初始化正确。

假设上方与左方集合已经完整、正确。任何到达当前格子的路径，最后一步必来自其中之一；将前缀异或值与当前格子异或，便得到这条完整路径的代价。因此，每条合法路径的结果都会加入当前集合，不会遗漏。

反过来，插入的每个状态都由一条合法前缀路径加上当前格子形成，不会产生不存在的路径。去重只合并相同结果，不影响后续可得到的值。

按遍历顺序，这个结论可以从起点逐格推广到终点。终点集合恰好包含全部合法路径的代价，取最小值便得到题目要求的答案。

## 复杂度分析

设任意格子的可达异或值集合大小最多为 K。

- 期望时间复杂度为 O(m × n × K)：每个格子最多枚举上方、左方各 K 个状态；哈希集合插入平均为 O(1)，最后取最小值需要 O(K)。
- 辅助空间复杂度为 O(m × n × K)：当前实现为每个格子保存一个状态集合。

这里 K 取决于输入的数值范围和实际可达结果，不能只因为使用了二维 dp，就把复杂度写成 O(m × n)。集合去重减少了重复路径的记录，但仍要为不同的异或状态付出时间和空间。

这道题的关键，是发现异或不满足“当前更小，后面也一定更优”的关系。保留所有不同的可达值，再在终点比较大小，才能避免过早丢失答案。
